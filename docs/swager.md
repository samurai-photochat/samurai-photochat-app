## GraphQL Endpoints

GraphQL предоставляет гибкий и эффективный способ получения данных с сервера. Это позволяет клиентам запрашивать только те данные, которые им действительно нужны.

### Playground

**Playground** — это интерактивный инструмент для исследования вашего GraphQL API.  
**URL:** <https://inctagram.work/api/v1/graphql>

### Аутентификация

GraphQL API требует Basic authentication для всех запросов, за исключением запроса `loginAdmin`. Для использования API необходимо предоставить действительные учетные данные в заголовке запроса.

### WebSocket для подписок

GraphQL поддерживает оба протокола для подписок:

- `subscriptions-transport-ws` (устаревший, для обратной совместимости)
- `graphql-ws` (современный)

**WebSocket endpoint:** `ws://inctagram.work/api/v1/graphql`

## WebSocket Communication

### Общая информация

WebSocket соединения обеспечивают канал связи в реальном времени между клиентом и сервером. Для получения уведомлений в реальном времени клиенты должны подключиться к WebSocket endpoint и слушать определенные события.

**WebSocket URL:** `https://inctagram.work`

### Требования к подключению

При подключении клиенты должны включить `accessToken` в качестве параметра запроса для аутентификации:

```javascript
const queryParams = {
  query: {
    accessToken: "your_access_token_here",
  },
}
io("https://inctagram.work", queryParams)
```

---

### События уведомлений

Клиенты должны слушать событие `NOTIFICATION` для получения уведомлений в реальном времени.

**Пример объекта уведомления:**

```json
{
  "id": 1,
  "clientId": "a1ea1061-9d07-4ae5-ad46-2d874769ed03",
  "message": "Your notification message here",
  "isRead": false,
  "notifyAt": "2025-10-02T16:07:34.372Z"
}
```

---

### События мессенджера

#### **RECEIVE_MESSAGE**

Используется как для отправки, так и для получения сообщений. При отправке сообщения сервер сохраняет его и возвращает сохраненное сообщение отправителю через событие `RECEIVE_MESSAGE`. Получатель получает то же сообщение через событие `MESSAGE_SENT`.

**Тип запроса:**

```json
{
  "message": "string",
  "receiverId": "number"
}
```

**Подтверждение получения:**

```javascript
callback({ message: message, receiverId: 1 })
```

#### **MESSAGE_SEND**

Получатель использует это событие для получения сообщений типа `MessageType`.

#### **UPDATE_MESSAGE**

Для обновления сообщения (пользователь может обновить сообщение, если он его создатель).

**Тип запроса:**

```json
{
  "id": "number",
  "message": "string"
}
```

#### **MESSAGE_DELETED**

Событие удаления сообщения. Сервер возвращает id удаленного сообщения.

#### **ERROR**

Для обработки ошибок. Сервер отправит сообщение об ошибке по пути ERROR.

**Тип ошибки:**

```json
{
  "message": "Error occurred",
  "error": "UPDATE_MESSAGE"
}
```

---

### Типы сообщений

**Message Type:**

```json
{
  "id": 1,
  "ownerId": 1,
  "receiverId": 2,
  "messageText": "TEXT",
  "status": "SENT",
  "messageType": "string",
  "createdAt": "2025-10-02T16:07:34.372Z",
  "updatedAt": "2025-10-02T16:07:34.372Z"
}
```

**Message Status Enum:**

- `SENT` — Сообщение отправлено, но еще не доставлено получателю
- `RECEIVED` — Получатель получил сообщение, но еще не прочитал его
- `READ` — Получатель прочитал сообщение

---

### Пути событий WebSocket

```javascript
const WS_EVENT_PATH = {
  RECEIVE_MESSAGE: "receive-message", // Отправка и получение сообщений
  UPDATE_MESSAGE: "update-message", // Обновление сообщения
  MESSAGE_DELETED: "message-deleted", // Удаление сообщения
  MESSAGE_SEND: "message-send", // Отправка сообщения получателю
  NOTIFICATIONS: "notifications", // Получение уведомлений
  ERROR: "error", // Обработка ошибок
}
```

**Примеры использования:**

```javascript
socket.on(WS_EVENT_PATH.RECEIVE_MESSAGE, (data) => {
  console.log("Receive message:", data)
})

socket.on(WS_EVENT_PATH.UPDATE_MESSAGE, (data) => {
  console.log("Message updated:", data)
})
```
